# Следовать плану

## 1. Определить $PLANPATH

`$PLANPATH` — общая папка для планов всех задач, путь относительно корня проекта.
Хранится в `.claude/local/config.md` строкой `PLANPATH: <путь>`.

- `PLANPATH` задан → использовать его, у пользователя не спрашивать.
- Файла нет или `PLANPATH` пустой → один раз спросить у пользователя путь и записать его в `.claude/local/config.md` (создать файл, если его нет; остальные строки не трогать). Больше не спрашивать.
- Пользователь сам назвал другой путь → работать с ним и спросить, сохранить ли его как новый `PLANPATH`.

## 2. Определить папку задачи `$PLANPATH/<some_id>`

Каждая задача (тикет) — отдельная папка `$PLANPATH/<some_id>`. Все задачи в одну папку не складывать.

`<some_id>` выбирает пользователь: полный номер тикета (`MEGAMIND-1234`) или сокращение (`mm-1234`).

1. Подсмотреть номер тикета в текущей ветке: `git branch --show-current`.
2. Если в `$PLANPATH` уже есть папка этого тикета (под полным номером или сокращением) — работать в ней.
3. Иначе предложить пользователю `<some_id>` по номеру тикета из ветки и спросить, как назвать папку. Если в ветке номера нет — спросить `<some_id>` у пользователя.

## 3. Структура папки задачи

```
$PLANPATH/<some_id>/
├── PLAN.md      # главный файл плана
├── research/    # ресерч (может отсутствовать)
├── results/     # результаты (может отсутствовать)
└── tmp/         # промежуточные файлы (может отсутствовать)
```

**PLAN.md** — это:
- краткое содержание всего изученного;
- список того, что надо сделать;
- отдельный список того, что ещё не сделано.

**research/** — ресерч, на котором основан план.

**results/** — глобальные результаты всей работы, а не отчёты по отдельным пунктам. Пример: сделали много всего и в итоге оптимизировали CPU на 20% — это и пишем, со всеми ссылками (коммиты, PR, эксперименты, ресерч и т.д.). Здесь несколько файлов, а не 20–30: например, один файл на эксперименты (если они были), один на то, что было написано в коде, и т.д.

**tmp/** — все остальные промежуточные файлы по задаче.

## 4. Как работать

### Плана ещё нет

Если `PLAN.md` в папке задачи нет — его сначала надо написать:
1. Провести ресерч по задаче, материалы сложить в `research/`.
2. Написать `PLAN.md` по структуре выше: краткое содержание изученного, список того, что надо сделать, и отдельный список того, что ещё не сделано.

### План есть

1. Прочитать `PLAN.md` целиком. В `research/` и `results/` заглядывать, когда это нужно.
2. Пункты не обязательно делать подряд. Разделить невыполненные пункты (без `[x]`) на независимые и те, что зависят от других.
3. Предложить пользователю, что можно сделать сейчас. Независимые подзадачи можно запускать в разных агентах параллельно.
   В задании каждому агенту указывать, куда сохранять: временные вещи — в `tmp/`, основное — в `research/` папки задачи.
4. Выполненный пункт отметить в `PLAN.md` галочкой: `- [ ]` → `- [x]`. Ничего не убирать из списков.
5. По отдельным пунктам результаты не писать. В `results/` писать только глобальный итог работы — со ссылками на всё, что к нему относится.
