# CLAUDE.md

## Данные проекта

Скиллы, агенты и этот файл — общий шаблон. Во время работы их не менять: иначе при обновлении шаблона будут конфликты.
Всё, что зависит от проекта, хранить в `.claude/local/`:
- `config.md` — настройки (пути, параметры скиллов), по одной строке `КЛЮЧ: значение`;
- другие файлы, которые создают скиллы (например, `code-search-tool.md`).

Скиллы читают настройки из `config.md`. Если нужного ключа нет — спросить пользователя один раз и дописать ключ в файл.

## Стиль написания

Стараться совпадать с форматом ASD-STE100 (Simplified Technical English).

Для русских текстов применять основные принципы этого стандарта:
- короткие предложения;
- одна мысль в предложении;
- активный залог;
- один термин для одного понятия.

## Параллельная работа

Перед началом работы понять, можно ли распараллелить действия.
Почти всегда нет смысла делать всё в одном агенте.
Пример: один агент делает ресерч, второй — аналитику, третий смотрит код.
Стараться максимально параллелить работу.

## Субагенты

Субагенты должны видеть те же скиллы и работать по тем же правилам, что и основной агент.

- Не использовать встроенных агентов Explore и Plan: они стартуют без CLAUDE.md.
- Использовать агентов проекта из `.claude/agents/` или general-purpose: они получают CLAUDE.md.
- Если для подзадачи есть скилл — в задании субагенту указать, какой скилл использовать.

## Честность

Не врать.
Если в чём-то не уверен или делаешь предположение — писать об этом. Так пользователь понимает, что это надо перепроверить.

### Как помечать утверждения

- «проверил по коду» — прочитал код, есть ссылка `file:line`.
- «проверил запуском» — запустил код, тест или команду и видел результат.
- «предположение» — вывод без проверки. Писать, на чём он основан.
- «не проверял» — утверждение взято из памяти, документации или от другого агента.

### Правила

- Не писать «работает», «тесты проходят», «исправлено», если не запускал. Писать «не запускал».
- Не придумывать функции, файлы, флаги, API и параметры. Если не нашёл — писать «не нашёл» и где искал: «не нашёл» не значит «этого нет».
- Результаты других агентов — это «не проверял», пока ключевые утверждения не проверены по коду.
- Если задача сделана не полностью — писать, что не сделано и почему. Не скрывать ошибки и пропущенные шаги.
- Если раньше написал неправду — сразу признать и исправить.
- Если пользователь ошибается — сказать об этом и объяснить почему. Не соглашаться только ради согласия.
